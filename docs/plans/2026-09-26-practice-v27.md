# v27 方案：选词列表能收回 + 过一遍不再重复词头与音标

> 状态：**已实施并通过验收**（2026-09-26）。真机反馈（截图）里的两个问题：
> ① 选词列表展开后收不回去；② 卡片里同一个单词（和它的音标）出现了两次，要删掉下面那个。

---

## 1. 选词列表收不回去

**原因不是"按钮坏了"**（点收起的逻辑一直是好的，只是没人测过这条路径）：

- `.picker` 自己有 `max-height: 40vh; overflow: auto` —— 列表是限高的、**内部能滚**
- 展开后页面还会往下多出一点，于是：页面滚下去 → 右上角「收起」滚出屏幕 → 想滚回顶部，
  但**手指落在列表上 → 滚的是列表，不是页面** → 按钮再也够不着，体感就是"收不回去了"
- 再叠加 v24 的旧设计：跳题之后列表**故意**保持展开（方便连着跳），更强化了这个感觉

**改法**

| # | 改什么 | 在哪 |
|---|---|---|
| a | **展开期间顶栏吸顶**：给视图挂 `.picker-open`，`.prac-top` 变 `position: sticky; top: var(--safe-t)`（吸在状态栏下面 + 一道细阴影） | `togglePicker()` + `style.css` |
| b | **点一行跳题后自动收起**：挑完就走；收起时不去刷新列表 DOM，下次展开那一刻再刷 | `jumpTo()` |

## 2. 同一个词和音标出现两次

**原因**：揭晓块"要不要补一行词头 + 音标"的开关只看了方向：

```js
answerTerm.hidden = !(s.curDir === 'zh2en');   // 旧
```

而 `s.curDir` 是**每个词按 id 哈希算出来的**（`dirForWord`），过一遍模式也会算出一个方向。
这一题恰好被算成"中→英"，于是揭晓块顶部又补了一行 `dispose /dɪsˈpəʊz/` —— 可过一遍模式下
题目（prompt）本来就是那个词、音标也在 `hint` 行里，等于同一份信息写了两遍。

**改法**：条件收紧成"只有当题目里没出现过词头时才补"：

```js
const showTermRow = !s.review && s.curDir === 'zh2en';   // 过一遍永不补
```

删掉的就是"下面那个单词及其音标"；题面上的词头与音标（`prompt` / `hint`）保持不动。
