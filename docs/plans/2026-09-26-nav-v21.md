## 二、⚠️ 对不上的地方

你说的是「**缩短**悬浮囊、**增加宽度**」，但量出来视频里那颗是：

- **横着更短**：274pt vs 我们 334pt（也就是左右留白更大，58 vs 28）
- **竖着更高**：61pt vs 我们 52pt
- **整体更靠下**：下沿 21pt vs 我们 46pt

也就是说：**视频里的胶囊比我们的更"瘦高、更贴底"**，和我们现在的方向正好相反。

两种可能，你选一个：

**A（推荐）按"1:1 复刻"做** —— 以上表实测值为准：
`左右留白 15%（≈58pt）` / `高 60pt` / `下沿 max(12px, safe-b − 13px)`（iPhone 上 ≈21pt）
理由：你说的目标是"1:1 复刻视频"，而实体测量是客观的；"缩短 + 加宽"更像是对画面的口头印象。

**B 按字面意思做** —— 高 52 → **46pt**，宽 334 → **358pt**（左右留白 28 → 16）。
结果：比例变成 7.8:1 的长条，**和视频（4.5:1）差得更远**，我不建议，但你要的话照做。

## 三、具体改动

### 1. 胶囊（按 A）
```css
#tabbar {
  left: 15%; right: 15%;                                   /* 宽 ≈70%（实测 68~71%） */
  bottom: max(var(--sp-3), calc(var(--safe-b) - 13px));     /* 实测下沿 21pt：比安全区还低 13pt */
  padding: 6px;                                             /* 内高 48 → 每格 48pt（≥44 无障碍下限） */
}
#tabbar a { min-height: 48px; padding: 6px var(--sp-1); }   /* 图标 22 + 间隙 2 + 文字 12 = 36，居中 */
```
- 图标 22 → **24pt**、文字 11 → **12pt**（内容带从 31.7 → 36pt，对齐实测）
- **材质**：把页面底与卡片对调（`--bg: #f2f2f7`、`--card: #ffffff`）—— 现在我们是"白底 + 灰卡"，iOS 的惯例是"灰底 + 白卡"；只有对调后，半透明的胶囊才会像视频里那样"比页面更亮"，否则永远是白压白、只看得见阴影。
  - 连带：`tool/check_contrast.py` 重跑（白卡对比度更好，不会变差）；深色模式本来就是 card 比 bg 亮 ✓ 两边终于一致
  - 如果你不想动整体配色，就跳过这条，代价是胶囊永远靠阴影辨认
- 宽屏那条媒体查询里固定 420px 的逻辑保留不动

### 2. 删掉词库行的说明文字 + 统一大小

统一尺寸：

### 3. 圆角加大
`--r-md`(12) → 用在卡片的改成 `--r-lg`(16)：`.card`、`.lib-row`、`.newlib-row`、`.empty`、`.lib-menu`、`.settings-plan`。
胶囊保持整圆（`--r-full`）；细长进度条保持 3px（否则像胶囊）。

### 4. 「过一遍」的左右滑动 → 真·1:1 拖拽（你说的第 1 项）
`src/ui-practice.js` 现在：记起点、跟手移动 ✓、松手按"距离 > 24px 或速度"二选一决定去留 ❌（没有速度接管、没有惯性投射、不能中途抓回来）。

按 apple-design 的配方重写：

| 配方 | 实现 |
|---|---|
| 1:1 跟手 + 抓住点偏移 | `setPointerCapture`，位移 = 当前指针 − 按下点（本来就没有中心跳变 ✓ 保留） |
| 速度历史 | 保留最近 5 个 `pointermove` 的 `(t, x)`，用**最近 80ms** 的窗口算手指末速 |
| 惯性投射 | 新增 `project(v, d=0.998) = (v/1000)·d/(1−d)`：落点 = 当前位移 + 投射距离 |
| 判定 | 落点超过 `0.35 × 卡宽`（≈130px）→ 切换；否则回弹。另保留"轻扫"分支：`|v| > 500px/s` 且方向一致 → 切换 |
| 速度接管 | 松手时把手指速度交给弹簧（新增 `src/spring.js`，约 40 行 rAF 弹簧积分器，`damping 0.8 / response 0.32`，就是 Apple 的抽屉参数） |
| 可打断 | 飞行中 `pointerdown` → 从**当前屏幕位置**读取并接管（不是从逻辑起点），不锁输入 |
| 橡皮筋 | 第一张往右拖 / 最后一张往左拖：位移按 `rubberband(x, w)` 阻尼，松手必回弹 |
| 减弱动效 | `prefers-reduced-motion` 下跳过弹簧，直接瞬时落位 + 淡出 |

T3 的 5 条浏览器断言（都靠 rAF 采样 `transform`，不靠肉眼）：
1. 轻扫（dx 40px、v 1200px/s）→ 投到下一张（按 `project()` 算出的落点判定）
2. 慢拖 120px 松手 → 距离够，切换
3. 慢拖 60px 松手 → 回弹，且**松手后第一帧的位移速度 ≈ 手指末速**（比值落在 0.6~1.4）
4. 飞行中 `pointerdown` → 位移从当前位置继续（相邻帧位移连续，无跳变 > 8px）
5. 第一张右滑 120px → 实际位移 < 手指位移（阻尼生效），松手回弹到 0
